# Configuration files

`dockerize` reads two optional files from the instance's `config/` folder.
Both are committed with the instance.

```text
instances/myapp/config/
├── build.json
└── apt-dependencies.txt
```

## build.json

Lists the git repositories to include in the image, besides the instance
repository itself. The format is the one written by
`gnr app dockerize --build-gen`:

```json
{
  "dependencies": {
    "git_repositories": {
      "erpy": {
        "url": "git@github.com:myorg/erpy.git",
        "branch_or_commit": "develop",
        "subfolder": null,
        "description": "ERPy packages"
      },
      "shared-tools": {
        "url": "https://github.com/myorg/monorepo.git",
        "branch_or_commit": "v2.3.1",
        "subfolder": "projects/shared_tools",
        "description": "Shared tools project"
      }
    },
    "docker_images": []
  }
}
```

Each entry of `git_repositories` is keyed by a free label and has these
fields:

`url` (required)
: Git URL, SSH (`git@github.com:org/repo.git`) or HTTPS. The repository's
  folder name in the image is the last part of the URL, without `.git`.

`branch_or_commit`
: Branch, tag or commit to check out. Default: `master`.

`subfolder`
: Only for repositories that contain a Genropy project in a sub-folder.
  The sub-folder is copied as `/home/genro/genropy_projects/<last part of
  subfolder>`. When `subfolder` is nested (contains `/`), the whole
  repository is copied too, under its own name. Default: none.

`description`
: Free text, written as a comment in the Dockerfile.

`docker_images` is accepted for compatibility and ignored.

Rules:

- Repositories are processed in file order.
- Two entries with the same URL (SSH and HTTPS forms count as the same) are
  merged; the last one wins.
- Two different repositories with the same folder name are an error.

### The instance repository in build.json

`build.json` files generated by Genropy usually list the instance repository
too. `dockerize` recognizes it by comparing its URL with the `origin` remote of
your checkout:

- By default the local checkout is used anyway. If `branch_or_commit` names
  neither the current branch nor the `HEAD` commit, you get a warning.
- With `--clone-main`, that entry is honoured: the repository is cloned from
  `url` at `branch_or_commit`.

If the instance repository is not listed, it is added automatically.

(generating-buildjson)=
### Generating build.json

Generating the file needs Genropy, because the list of required packages comes
from loading the application. Two options:

- On a machine with Genropy, run `gnr app dockerize myapp --build-gen` once,
  then commit `config/build.json`. Regenerate it when dependencies change.
- Write it by hand: it only needs `url` and `branch_or_commit` for each
  repository.

Without `build.json`, the image contains only the instance repository and a
warning is printed.

## apt-dependencies.txt

Debian packages to install in the image, on top of the base image:

```text
# PDF generation
wkhtmltopdf
# Imaging
libjpeg62-turbo libpng16-16
```

- One or more package names per line, separated by spaces.
- `#` starts a comment; blank lines are ignored.

The packages are installed as root, before the sources are copied:

```dockerfile
RUN apt-get update && apt-get install -y --no-install-recommends wkhtmltopdf libjpeg62-turbo libpng16-16 && rm -rf /var/lib/apt/lists/*
```

## Environment variables

`GNR_LOCAL_PROJECTS`
: A folder containing projects; searched as `*/instances/NAME` when looking
  up an instance by name.

`GENRO_GNRFOLDER`
: Folder holding Genropy's `environment.xml`. Default: `~/.gnr`. Its
  `instances` and `projects` paths are used for the instance lookup.

Neither is needed when you pass the instance path or run from the project
folder.
